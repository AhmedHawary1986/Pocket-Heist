# Spec for signup-firebase-auth

branch: claude/feature/signup-firebase-auth  
figma_component (if used): N/A

## Summary
- Wire the existing signup form in `app/(public)/signup/page.tsx` to Firebase Authentication using `lib/firebase.ts`
- On successful signup, generate a random display name (codename) by combining one word from each of three distinct word sets in PascalCase
- Create a Firestore document in the `users` collection storing only the user's `id` and `codename` (no email)

## Functional Requirements
- The signup form submits email and password to Firebase Auth (`createUserWithEmailAndPassword`)
- After account creation, update the Firebase Auth user profile with the generated `displayName`
- The codename is generated by picking one word from each of three unique word sets (e.g., adjective + noun + role) and joining them in PascalCase
- Each word set must contain words that are thematically unique from the other sets
- After setting the display name, write a document to the `users` Firestore collection with fields: `id` (Firebase Auth UID) and `codename` (the generated display name)
- Email must NOT be stored in Firestore
- Only the Firebase Web SDK may be used (no Admin SDK, no server-side Firebase calls)
- On success, redirect the user to the dashboard (e.g., `/heists`)
- On failure, display an inline error message to the user

## Possible Edge Cases
- Firebase Auth error (e.g., email already in use, weak password) — show user-friendly error message
- Firestore write fails after Auth account creation — user account exists but has no Firestore doc; should be handled gracefully
- Codename collision in Firestore is acceptable (no uniqueness enforcement required at this stage)
- Network offline during signup

## Acceptance Criteria
- Submitting valid credentials creates a new Firebase Auth user
- The new user's `displayName` is set to a randomly generated PascalCase codename
- A document exists in the `users` collection with the correct `id` and `codename`, and no `email` field
- Auth errors surface as readable messages in the UI
- Successful signup redirects to the authenticated area

## Open Questions
- Should the redirect destination after signup be `/heists` or a different route?
- Should codename generation be retried if the Firestore write fails?

## Testing Guidelines
Create a test file(s) in the ./tests folder for the new feature, and create meaningful tests for the following cases, without going too heavy:
- Codename generator returns a non-empty PascalCase string combining one word from each set
- Codename generator produces different results across multiple calls (randomness check)
- Firestore document written on signup contains `id` and `codename` but not `email`
- Auth error during signup surfaces an error message in the UI
